# 原子控件生成与操作打包衔接说明

本文专门回答这个问题：

> 我已经能筛选出合适控件并导出 JSON，下一步怎么把它“传送到原子控件生成”，再变成“微信操作打包”里可选的标准控件？

---

## 1. 先理解三个层次（避免流程混淆）

1) **候选节点层（AT-SPI）**
- 来源：AT-SPI 抓树 / 高级筛选 / 聊天容器发现 / 弹窗发现。
- 结果：候选节点（只是“可能可用”，还不是标准控件）。

2) **标准控件层（UI Control Library）**
- 存储：`wechat_ui_control_definition`（后端接口 `/api/v1/wechat/ui/controls`）。
- 结果：有 `control_uid`、`profile_id`、bounds、actions、meta 的“标准控件”。

3) **动作包编排层（微信操作打包）**
- 页面：微信操作打包。
- 调用：按 `profile_id + control_uid` 引用标准控件。

结论：**你要做的是把“候选节点”转换成“标准控件”，然后动作包才能选择。**

---

## 2. 你当前场景的标准流程（推荐）

### 步骤 A：筛选候选控件（你已会）
可用任一方式：
- 高级查询（role/depth/name/path 等）
- 聊天容器发现
- 弹窗控件发现
- 已校准控件列表

如果要备份，先导出 JSON（这一步是“候选数据备份”）。

### 步骤 B：传送到“原子控件生成”并人工选择
在 `RPATest` 的“6.生成原子控件（供微信操作打包调用）”里做：

- 填 `profile_id`（必须，后续操作打包按它加载控件库）。
- 在“选择已校准控件”中选你确认过的控件。
- 点击“从已校准控件同步”。
- 检查并补全：`control_uid`、控件名称、`region_key`、`control_type`、主动作。
- 点击“保存为标准控件”。

这条链路是**逐个人工确认**，最稳。

### 步骤 C：批量生成（可选，加速）
如果你已经把筛选条件收敛得很准，可直接批量：
- 从聊天原子容器生成控件
- 从弹窗原子容器生成控件
- 从高级查询生成控件

底层接口：`POST /api/v1/wechat/ui/controls/generate_from_atomic`

注意：批量会直接入库，不是先勾选后入库。建议先小 `limit` 试跑，再删除不合格项。

### 步骤 D：进入微信操作打包使用
在“微信操作打包”页面：
- 动作包设置里填同一个 `profile_id`。
- 点击“加载控件库”。
- 在步骤里选择 `control_uid`。

到这一步就完成了“变成微信操作打包里可选控件”。

---

## 3. 你说的“筛选 JSON 后下一步怎么弄”对应关系

你现在习惯：**先筛选 -> 导出 JSON**。
下一步有两种：

### 路线 1（稳妥，推荐）
JSON 仅做参考 -> 在“生成原子控件”页逐个挑选并“保存为标准控件”。

适用：关键流程（发送按钮、输入框、第一联系人等核心控件）。

### 路线 2（快）
把筛选规则转为 `filters` -> 调 `generate_from_atomic` 批量入库 -> 在控件库里删错的。

适用：一次性扩库、容器类控件、弹窗菜单项。

---

## 4. 最小可执行 SOP（照着点就行）

1. 打开微信并保持目标界面（聊天页或弹窗页）。
2. 在原子相关页面完成筛选，确认候选节点看起来正确。
3. 打开“6.生成原子控件”。
4. 输入 `profile_id`。
5. 选择候选控件并“从已校准控件同步”。
6. 点击“保存为标准控件”。
7. 点击“加载已生成控件”，确认已入库。
8. 打开“微信操作打包”，填写同一个 `profile_id`。
9. 点击“加载控件库”，在步骤中选择 `control_uid`。
10. 保存步骤并执行验证。

---

## 5. 关键字段建议（避免后面难维护）

- `control_uid`：稳定命名，建议含语义，如 `chat.first_contact`、`chat.input`、`chat.send_button`。
- `profile_id`：同一套界面模板必须复用同一个 id。
- `region_key`：建议固定在 `contact_list / chat_display / chat_input / main_menu` 等。
- `actions`：至少包含首要动作（如 `click` 或 `input_text`）。
- `meta.atomic_profile_name`：若来自原子配置，建议保留，方便后续 AT-SPI 原子动作回退。

---

## 6. 常见坑位

- **没填 profile_id**：控件保存了但打包页看不到（或加载为空）。
- **批量生成太宽**：一次灌入太多噪声控件，后续难清理。
- **control_uid 冲突**：会覆盖/冲突，建议命名先定规则。
- **窗口状态变化大**：先激活微信并刷新辅助树，再做定位与生成。

---

## 7. 一句话总结

你要做的核心就是：**把“筛选结果（候选）”通过原子控件页转成“标准控件入库”，然后在操作打包按 `profile_id + control_uid` 直接选用。**

---

## 8. 2026-02 前端已落地的顺滑链路（第7步 -> 第6步）

现在页面已经支持一键衔接，不再需要手工来回复制：

1) 在“7.原子容器设置管理”里完成高级查询（最好收敛到唯一控件）。
2) 在“链路落地：生成配置文件并带入生成原子控件”区块：
	- 填 `目标 profile_id`
	- 点“生成配置文件”
	- 点“保存并带入第6步”
3) 切到“6.生成原子控件”，在“来自第7步的配置文件”区块点：
	- “应用到当前生成器”（仅填充参数，不执行）
	- 或“按配置直接生成控件”（直接执行 query 批量生成）
4) 生成后刷新“已生成原子控件列表”确认入库。
5) 打开“微信操作打包”，填同一 `profile_id`，加载控件库并选择 `control_uid`。

这样就完成了“全局查询定义 -> 生成配置文件 -> 生成原子控件 -> 操作打包引用”的完整闭环。
